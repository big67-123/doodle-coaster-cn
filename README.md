# 涂鸦过山车 · Doodle Coaster CN

**▶ 在线试玩：<https://big67-123.github.io/doodle-coaster-cn/>**（手机浏览器直接打开，不用装任何东西）

随手画一条线，它就会变成一条真的过山车轨道 —— 然后第一人称坐上去。

原版是 [らくがきコースター / Doodle Coaster](https://rakugaki-coaster.pages.dev/)（作者 [@kikuchitls](https://x.com/kikuchitls)），
这个仓库是在它基础上的中文衍生版：**界面全中文**、加了**速度 / G 值仪表**、加了**可调电磁弹射（100–10000 km/h）**、
留了一个**自己设计轨道的口子**（文件槽 + 页内粘贴 + 可视化编辑器）。

零依赖、零构建：仓库根目录就是站点根目录，扔进任何静态托管都能跑，直接双击 `index.html` 也能跑。

## 玩法

| 操作 | 说明 |
|---|---|
| 画轨道 | 在屏幕上一笔画一条线，松手即生成轨道（至少要 25 米） |
| 出发 | 点「▶ 出发」按重力起步；点「⚡ 电磁弹射」按滑杆上的速度弹射出去 |
| 弹射速度 | 滑杆是对数刻度，100 → 10000 km/h；四个快捷档 300 / 1k / 3k / 10k |
| 仪表 | 乘坐时左下角实时显示速度（km/h）和 G 值；G 条按对数刻度，白线是本次峰值。负 G 时标题会变成「失重」—— 那是真的被甩离座位，不是故障 |
| 慢动作 | 右下角按钮或键盘 `S` 循环切换目标观感时长（原速 / ≈10s / ≈20s / ≈45s）。出发前会先无头模拟出真实车程再反推缩放系数，所以任何轨道都落在同一个观感时长附近 |
| 轨道尺度 | 一屏宽固定代表约 200 米世界：画满一屏约 200 米轨道，重力起步车程约 20 秒 |
| 轨道工坊 | 右上角 🛠。列出 `tracks.js` 里的轨道，可粘贴 JSON 试跑、导入导出、进编辑器 |
| 编辑器 | 拖圆点移动控制点，点空白处插点，双击圆点删点，`Ctrl+Z` 撤销 |
| 分享 | 成绩卡上有分享链接。手绘轨道用原版的 `#t=` 紧凑编码，设计出来的轨道用 `#j=` JSON 编码 |

## 想加一条自己的轨道？

打开 `tracks.js`，往数组里追加一项：

```js
{
  id: 'my-ride',                 // 英文/数字标识，用来区分
  name: '我的轨道',
  ground: 70,                    // 地面高度（米），决定 h = 0 落在哪
  launch: 300,                   // 默认弹射速度 km/h；填 0 或省略 = 重力起步
  note: '随便写点什么',
  points: [[0, 0], [40, 30], [80, 44], [120, 6], [160, 0]],
}
```

`points` 是控制点数组，每一项是 `[x, h]`：

- `x` = 距起点的米数
- `h` = **离地高度**（向上为正，单位米，最低 0）。不用关心画布大小。
- 这些点就是 Catmull-Rom 样条的控制点本身，不做额外平滑 —— 你放哪，轨道就过哪。
- 内置了 `loopPoints(cx, ch, r)` 可以生成一个立环的控制点，见 `vertical-loop`。

改完刷新页面，就能在「轨道工坊 → 我的轨道」里看到并试跑。

## 物理说明（这块是重点）

单位就是米和秒：`1 单位 = 1 米`，速度变量就是 m/s（所以 km/h 只要 × 3.6）。

### 与原版的兼容性

普通乘坐（速度低于 60 m/s ≈ 216 km/h）**和原版逐位一致**，这不是估计，是测试断言的事实
（`test/physics.test.mjs` 拿原版实现跑出的黄金基线逐帧比对）。超过 60 m/s 后自适应子步开始起作用，
偏差在 0.008% 量级，而且比原来更准。

### 三处改动

| 改动 | 原因 |
|---|---|
| **自适应子步** | 原版固定 `1/240 s`。10 000 km/h = 2778 m/s 时每子步前进 11.6 米，而轨道采样间距只有 0.25 米 —— 会直接穿过轨道。现在每子步最多前进一个采样间距（`h = min(SUB, 0.25/|v|)`），低于 60 m/s 时它恰好等于原值。 |
| **阻力封顶** | 原版 `DRAG·v²` 在 2778 m/s 下是 6173 m/s²（约 629 G），半秒内把车吃光。所以封顶在 3 m/s² —— `v ≤ 61.2 m/s`（220 km/h）时与原式**逐位相同**，普通乘坐手感零变化。这是唯一的发布手感；原式仍留在 `physics.js` 里，`?test=1` 下 `__olc.setArcade(false)` 可切回对照，测试也持续覆盖两种模式。 |
| **限减速制动** | 原版在最后 14 米把速度**瞬间钳位**到 `max(1.5, 1.15·rem)`。普通速度下看不出来，但高速时那是一次 2300 m/s 的瞬跳。现在改成受 25 m/s² 限制的真实减速；把制动力设成无穷大时就退回原版行为。 |

### 电磁弹射怎么算的（液压性格，不是 LSM）

**先把性格归属说清楚**：行业里 LSM（直线同步电机）被描述为「平稳、由电脑精确计量的一推」，
而「突然、生硬的一脚」是**液压**和 LIM 的性格。这个版本做的是后者 —— 目标就是「被踹一脚」。
（来源：[thrillzing · LSM vs LIM](https://thrillzing.com/roller-coasters/roller-coaster-launch-systems/)）

加速度因此**不是恒定的**，而是真实电机的两段式形状：起步瞬间推力最大，速度上来后驱动受反电动势限制、
进入恒功率段，推力随速度回落：

> `a(v) = a₀`（v ≤ v_base，恒推力段）　　`a(v) = a₀ · v_base / v`（v > v_base，恒功率段）

取 `v_base = BURST_R × V`（`BURST_R = 0.45`），峰值 `a₀` 由「恰好走完弹射段、正好到达目标速度」反解：

> `a₀ = [ (v_base² − v₀²)/2 + (V³ − v_base³)/(3·v_base) ] / L`

`BURST_R = 1` 时它退化成旧的恒定加速弹射（`a₀ = (V² − v₀²)/2L`），这条恒等关系有测试守着。
弹射段长度从原来的 `clamp(轨道长×0.25, 25, 300)` 收紧到 `clamp(轨道长×0.15, 20, 60)` ——
长轨道上不再出现 300 米、三四秒的缓慢推背。

弹射段内速度是**位置的闭式函数**（前段 `v² = v₀² + 2a₀s`，后段 `v³ = v_base³ + 3a₀v_base(s−s₁)`），
所以剖面与积分步长无关、10 000 km/h 也精确 —— 那是运动学牵引，不是积分出来的。

实测（281 米手绘轨道，弹射段 42.1 米）：

| 目标速度 | 峰值 | 尾段 | 峰段时长 | 弹射总时长 |
|---|---|---|---|---|
| 100 km/h | **1.44 G** | 0.65 G | 0.78 s | **2.52 s** |
| 400 km/h（默认） | 23.1 G | 10.4 G | 0.21 s | 0.65 s |
| 1000 km/h | 145 G | 65 G | 0.09 s | 0.26 s |
| 10 000 km/h | ~14 500 G | ~6 500 G | 0.01 s | 0.03 s |

100 km/h 那一档对上真实 LSM 的量级（Blue Fire：0→100 km/h 用 2.5 秒，来源
[thrillzing · Blue Fire](https://thrillzing.com/roller-coasters/blue-fire-megacoaster-europa-park/)）。
**但速度越高力就越离谱**：真实 LSM 约 1.1–1.5 G，而 400 km/h 在 1.2 G 下需要约 520 米助跑、
10 000 km/h 需要 327 公里，手绘赛道根本装不下。所以高速度档位上的 G 是**奇幻量级**：曲线形状是真的，力不是。

**为什么 G 仪表上看不到这一脚**：仪表读的是比力沿乘客「上」轴的分量。平直弹射段上重力与该轴平行、
而弹射力是**纵向**的，两者投影恰好抵消 —— 平轨上弹射期间 G 恒等于 1。这是正确的物理，不是 bug。
所以弹射另给了两个出口：成绩卡上的「弹射峰值推背」（纵向比力 `at/G − ty` 的峰值）与弹射期间的镜头冲击。

达到目标速度后无缝交回原有动力学。

### 高速下的终点

10000 km/h 跑完一条 500 米轨道只要 0.18 秒，这是物理事实，不是 bug：

- 末端制动来不及发力，列车以近全速冲过终点（实测 2775 m/s）。
- 若切回原式阻力（`__olc.setArcade(false)`），空气会在 0.45 秒内吃光速度，最后在 14 米制动区被钳位。

两种都以 `ended = true` 正常结束，不 NaN、不倒退 —— 这些都有测试盯着。

### G 值是真的吗

是真的，而且是教科书公式：**比力 =（运动学加速度 − 重力）投影到乘客的「上」轴，再除以 g₀**，
最后过一个 τ=0.06 秒的一阶低通（原版就有，用来压手绘抖动的毛刺）。切向加速度与「上」轴正交，会被完全约掉，所以剩下

> `g = sigma·cosθ  ±  v² / (R·g₀)`

前一项是重力沿座椅方向的分量（平地上恰好 1），后一项是曲率带来的向心载荷：**凹曲率（山谷）取正，凸曲率（山脊、立环顶端）取负**。

**为什么会出现负数**：凸曲率处向心加速度朝下、与重力同向。当 `v²/R > g₀` 时比力反向 —— 座椅不再是把你压住，
而是要往下拽你，现实里就是你会被甩出座位（失重 / airtime）。立环顶端必须满足 `v²/R > g₀` 才坐得住，这是真实力学。

`test/gforce.test.mjs` 拿解析解逐帧对照，实测（弹射 400 km/h，取弧后段已收敛区）：

| 半径 R | 形态 | 解析解 | 实测 G | 偏差 |
|---|---|---|---|---|
| 200 m | 山谷 | +5.9 | +5.8 | 0.08 G |
| 120 m | 山谷 | +9.7 | +9.6 | 0.14 G |
| 60 m | 山谷 | +18.7 | +18.4 | 0.28 G |
| 200 m | 山脊 | −4.8 | −4.9 | 0.08 G |
| 120 m | 山脊 | −8.5 | −8.6 | 0.14 G |
| 60 m | 山脊 | −17.9 | −18.0 | 0.17 G |

残差**不是**误差，而是低通的动态滞后 `τ·|dG/dt|`：实测偏差与这个预测值之比是 **0.90–0.96**，扣掉它之后剩余不超过 0.06 G。
测试就是按这个机理断言的，不是拍一个容差。另外两条硬事实：平直轨道上 G 恒等于 `1.0000`（精确到 1e-9）；
建出的轨道曲率 `|k|` 与 `1/R` 一致到 0.3% 以内（曲率平滑没有把曲率抹掉）。

**它的边界**（别当成真车数据）：

- 这是**质点运动学模型**：没有悬挂、没有乘客自身的运动、没有阻尼、没有车体俯仰。
- 读数带 0.06 秒低通，所以**很短的尖峰会被低估** —— 实测入弧（19 G 阶跃）后约 0.1–0.2 秒追上解析解。
- 超过几 G 就已经不是人体可承受范围了，几万 G 只是几何算式的结果，不代表真实结构能存在。

## 本地开发与测试

也可以在本地直接双击 `index.html`（`physics.js` / `tracks.js` 都是经典 script，`file://` 下也能加载）。

```bash
node --test test/physics.test.mjs test/tracks.test.mjs test/gforce.test.mjs   # 物理 + 轨道校验 + G 值
node _tools/serve.mjs 8899                               # 本地静态服务器
```

`?test=1` 会挂出 `window.__olc`，可以在浏览器控制台里直接驱动：
`__olc.loadDef(def)`、`__olc.setLaunch(10000)`、`__olc.stats()`、`__olc.dry({launchKmh:10000})`、
`__olc.slowmo`（本次缩放系数）、`__olc.slowTarget`、`__olc.rideSimT`、`__olc.setSlowTarget(2)`、`__olc.setSlowFactor(10)`、
`__olc.enterEdit(def)`、`__olc.exportDef()`、`__olc.shareHash()` 等。

```bash
node _tools/bench.mjs        # 构建耗时
node _tools/converge.mjs     # 空间步长收敛性
```

### 文件结构

| 文件 | 作用 |
|---|---|
| `index.html` | 全部 UI、渲染、i18n、仪表、弹射、工坊、编辑器 |
| `physics.js` | 无 DOM 的纯数学：几何、积分器、无头 `simulate()`。既是浏览器里的经典 script，也能被 Node `require()` |
| `tracks.js` | 轨道定义槽 + 校验器，`file://` 下也能加载 |
| `test/` | `node:test` 测试，含从原版实现采集的黄金基线 `golden.json` |

> 注意 `physics.js` 必须按 CommonJS 语义加载。仓库里**故意没有** `package.json` 的 `"type": "module"`，
> 否则 Node 会把它当 ESM，`require()` 拿不到导出。
